# 🔤 概念层
概念层回答四个相互衔接的问题：内容由哪些对象与关系构成，呈现结果应怎样理解，技术入口具体表达什么，以及证据和测量怎样评价。[理论层的方法论基座](https://larkcommunity.feishu.cn/wiki/VZ07wyiPTi98xbkGi8JcwMIbnLb)提供判断方向，[机制层](https://larkcommunity.feishu.cn/wiki/CSAbwRmMiiBqHZkT7fAcseCxnlg)解释系统如何取得和处理信息；这里把后续讨论需要反复使用的术语、边界与计算口径讲清楚。

本层按 16 篇组织。原有 15 个词条全部保留在内容中，关系紧密的概念合并解释，同时补入任务与上下文、主张与必要条件、溯源与支持关系、可见性与有效呈现，以及权威性、来源锚定和测量基础。可以顺序阅读，也可以通过下方词条索引直接查阅。

## 六、不同概念的确定程度

**技术规范与公开词汇**有对应文档，例如 JSON-LD、Schema.org、sameAs 和 Robots Exclusion Protocol。使用时需要尊重其原始语义，并区分规范定义与具体平台支持。

**协议提案与具体实现**需要分别说明。llms.txt 有公开提案与版本变化，文档平台可以提供自己的实现；文件存在、工具读取和搜索效果仍是不同状态。

**工作概念**用于组织本知识库中的内容，包括实体主档、答案资产和证据图谱。它们借鉴身份管理、内容复用和溯源思想，正文会明确其用途，避免将工作命名宣称为通用行业标准。

**指标定义**必须带有计算口径。提及率、引用率与推荐率在本层采用明确的回答级定义；声量份额没有统一公式，正文分别解释工作口径与工具口径。引用缺口是一组诊断含义，不能脱离类型写成唯一数字。

## 七、贯穿本层的判断关系

主张以实体为对象，以条件限定范围，以证据提供支持。答案资产将这些关系组织成解释，证据图谱保存依赖；结构化数据与导航提供表达和入口，呈现指标则观察最终回答。各层之间的关系需要连接，也需要保留职责边界。

有效呈现沿用理论层的四项要求：**相关、准确、有据、适用**。仅有提及不代表事实正确，有引用不代表结论被支持，有推荐不代表对象适用，相对份额也不代表实际市场占有。后续工作可以同时提高适用需求中的覆盖，并减少不适用需求中的错误推荐。

将概念用于实际工作时，可以继续阅读[方法层导读](https://larkcommunity.feishu.cn/wiki/InnLwkfWmighMikrwItcw5SSnAc)。问题集、事实基线、评审记录和对照设计分别落实这些关系，版本与更正维护则使它们能够长期复查。
