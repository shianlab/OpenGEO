# 📐 方法层
[理论层的方法论基座](https://larkcommunity.feishu.cn/wiki/VZ07wyiPTi98xbkGi8JcwMIbnLb)提出问题、对象、主张、证据、表达与反馈之间的关系；[机制层](https://larkcommunity.feishu.cn/wiki/CSAbwRmMiiBqHZkT7fAcseCxnlg)解释资料如何进入回答；[概念层](https://larkcommunity.feishu.cn/wiki/WYHWwjmYViLhrikM1XJcQsGLngc)明确内容对象与评价口径。方法层进一步说明怎样组织实际工作，使内容缺陷、改动与结果能够相互追踪。

本层先建立评价、复核、验证和维护四项基础方法。它们适用于公开资料型问答、选型与推荐的研究和内容维护。正文给出操作设计、记录字段和说明性例子，实际效果需要按对应环境执行，不能将流程完备等同于效果已经验证。

## 一、从任务与事实开始

[01 · 评价设计：问题样本与事实基线](https://larkcommunity.feishu.cn/wiki/HKyJwM6ueiqXOrkhM3mcwKUOnbG)

确定评价要支持的决定，整理真实任务，区分指名与未指名、适用与不适用、开发与检验样本。围绕对象、主张、条件和材料建立事实基线，再固定运行、重复与失败处理。交付是可以复查的问题与依据。

## 二、让回答判断可以复核

[02 · 回答评审：标签规则与分歧处理](https://larkcommunity.feishu.cn/wiki/QqHmwHXbYiStDikQjcjcnLQlnUe)

分别判断提及、引用和推荐，检查事实、来源支持与必要条件，再汇总任务完成。通过独立标注、校准、分歧处理和模型评分验证，检查测量本身的质量。交付是带依据和版本的评审记录。

## 三、判断改动的结果与原因

[03 · 干预实验、重复测量与效果验证](https://larkcommunity.feishu.cn/wiki/X2VRwdmkAi8EhHkp50lcgVn3nRh)

将改动写成可检验假设，区分受控与公开环境，安排比较、重复与质量约束。记录任务关联、时间波动、暴露与干扰，说明观察到的变化及原因解释范围。交付是能够区分结果、推断与未知的比较结论。

## 四、让内容能够长期维护

[04 · 内容来源审核与更正维护](https://larkcommunity.feishu.cn/wiki/SHfqwgXgyiqBeokU9zbcms46nvg)

核对主张与文献身份，安排真实作者及复核责任，检查计算和跨篇衔接，再根据来源变化处理断链、更正与传播版本。交付是有依据的正文和可追踪的维护过程。

## 五、怎样沿用实施闭环

| 基座中的步骤 | 方法层主要支持 | 完成时需要看什么 |
| --- | --- | --- |
| 定题 | 第 01 篇 | 任务范围、来源、分组与用途明确 |
| 立据 | 第 01、04 篇 | 身份、事实、条件与证据可以复查 |
| 成文与供给 | 第 04 篇，结合机制层 | 内容范围正确，入口与版本可辨认 |
| 观测与诊断 | 第 01、02 篇 | 原始回答与判定依据完整 |
| 干预与比较 | 第 03 篇 | 改动、参照与不确定性有记录 |
| 固化与维护 | 第 03、04 篇 | 规则有适用范围，更正有责任 |

首次阅读可以按编号推进。问题样本不公平，先看第 01 篇；同一答案总被判成不同标签，看第 02 篇；结果变化却无法解释原因，看第 03 篇；引用、署名或新旧事实有问题，看第 04 篇。已有可靠记录可以继续沿用，缺失部分补齐，避免为了形式重复已经完成的核验。
